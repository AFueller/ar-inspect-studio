# Security Policy

Security fixes target the latest published release.

Do not open public issues for vulnerabilities that could expose credentials, user data, uploaded evidence, session state or database contents. Use GitHub private vulnerability reporting / Security Advisories when available.

Security-sensitive areas include authentication and roles, CSRF/session handling, uploads, setup/upgrade endpoints, inspection snapshot/revision integrity, exports, and WebXR/browser permission flows.

Operators remain responsible for HTTPS, server hardening, database permissions, backups, patching and access control.
